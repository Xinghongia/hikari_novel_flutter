# 第三章 项目依赖与技术栈

> pubspec.yaml 是理解项目技术选型的钥匙。

## 概述

Hikari Novel Flutter 的运行时依赖超过 40 个包，按功能可分为 9 大类：框架、网络、存储、浏览器、UI 组件、工具库、媒体、国际化和平台增强。开发依赖 5 个包用于代码生成和构建工具。

## 依赖分类详解

### 1. 框架层

```yaml
get: ^4.6.6
```

GetX 是项目的架构骨架，同时承担三个职责：

- **路由管理**：`GetMaterialApp` + `GetPage` 定义路由表，`Get.toNamed()` 导航
- **状态管理**：`.obs` 响应式变量 + `Obx()` 局部刷新
- **依赖注入**：`Get.put()` 注册 Controller，`Get.find()` 获取实例

### 2. 网络层

```yaml
dio: ^5.3.3
cookie_jar: ^4.0.8
dio_cookie_manager: ^3.1.1
```

- **Dio**：HTTP 客户端，支持拦截器、请求取消、FormData 上传
- **CookieJar**：Cookie 持久化，wenku8 的登录态（`jieqiUserInfo`、`jieqiVisitInfo`）依赖它
- **DioCookieManager**：Dio 拦截器，自动附加/保存 Cookie

配合自定义的 `CloudflareInterceptor` 处理 Cloudflare 403 挑战。

### 3. 存储层

```yaml
# NoSQL
hive_ce: ^2.11.1
hive_ce_flutter: ^2.3.0

# SQL ORM
drift: ^2.26.1
drift_flutter: ^0.2.4

# 路径
path: ^1.9.1
path_provider: ^2.1.5
```

双存储引擎并行：

| 引擎    | 用途                   | 数据结构                |
| ------- | ---------------------- | ----------------------- |
| Hive CE | 设置项、登录信息、阅读器配置 | 3 个 Box（setting/loginInfo/reader） |
| Drift   | 书架、浏览历史、搜索历史、阅读历史、小说详情 | 5 张 SQLite 表          |

### 4. 浏览器

```yaml
flutter_inappwebview: ^6.1.5
```

用于 WebView 登录流程。用户在嵌入式浏览器中登录 wenku8，App 通过 Cookie 监听自动捕获登录态。支持 Windows 和 Android 双平台。

## 开发依赖

| 库                    | 版本    | 用途                          |
| --------------------- | ------- | ----------------------------- |
| build_runner          | ^2.4.15 | 代码生成运行器                |
| drift_dev             | ^2.26.1 | Drift 数据库代码生成          |
| hive_ce_generator     | ^1.9.1  | Hive TypeAdapter 代码生成     |
| json_serializable     | ^6.10.0 | JSON 序列化代码生成           |
| flutter_lints         | ^6.0.0  | Lint 规则                     |
| flutter_test          | SDK     | 测试框架                      |

代码生成命令：

```bash
dart run build_runner build --delete-conflicting-outputs
```

这条命令会根据注解生成以下文件：
- `*.g.dart`：Drift 数据库表定义和 DAO
- `*.hive_registrar.g.dart`：Hive TypeAdapter 注册
- `*.json.dart`（如有）：JSON 序列化/反序列化代码

## 与 Kazumi 技术栈对比

| 维度     | Kazumi           | Hikari Novel         |
| -------- | ---------------- | -------------------- |
| 状态管理 | Riverpod         | GetX                 |
| 路由     | GoRouter         | GetX 内置            |
| 网络     | Dio + html       | Dio + html           |
| 数据库   | Drift            | Drift + Hive CE      |
| 视频播放 | media_kit        | 无（纯文本阅读）     |
| 弹幕     | 无               | 无                   |
| TTS      | 无               | flutter_tts          |
| WebView  | 无               | flutter_inappwebview |
| 动态取色 | 无               | dynamic_color        |

两个项目都选择了 Drift 作为 SQL ORM，但 Hikari Novel 额外引入了 Hive CE 做轻量级 Key-Value 存储。GetX 的"全家桶"模式让 Hikari Novel 的依赖数量看起来更多，但实际引入的架构概念更少（一个包解决三个问题）。
