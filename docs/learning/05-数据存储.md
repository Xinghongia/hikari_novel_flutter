# 第五章 数据存储：数据库与本地持久化

> 应用采用 Drift + Hive CE 双存储方案。Drift 负责结构化业务数据（书架、历史、阅读进度），
> Hive CE 负责键值配置（设置项、登录信息、阅读器偏好）。
> 两套引擎各司其职，通过 Service 层统一暴露给上层。

---

## 5.1 双存储架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                        UI / Controller                       │
│                     Get.find<DBService>()                    │
│                     LocalStorageService.instance              │
├──────────────────────────┬──────────────────────────────────┤
│       DBService          │       LocalStorageService         │
│    (GetxService)         │         (GetxService)             │
│    薄封装层               │         薄封装层                   │
├──────────────────────────┼──────────────────────────────────┤
│      AppDatabase         │         Hive CE                   │
│      (Drift ORM)         │      (Key-Value)                  │
├──────────────────────────┼──────────────────────────────────┤
│   SQLite (hikari_        │   3 个 Box:                       │
│   novel_database)        │   - setting (设置)                │
│   5 张表                  │   - loginInfo (登录)              │
│                          │   - reader (阅读器)               │
└──────────────────────────┴──────────────────────────────────┘
```

| 维度       | Drift (SQLite)                | Hive CE (NoSQL)              |
| ---------- | ----------------------------- | ---------------------------- |
| 数据类型   | 结构化业务数据                | 键值配置                     |
| 查询方式   | SQL 查询（支持 Stream 监听）  | 按 key 读写                  |
| 适用场景   | 书架、历史、阅读进度          | 设置、登录态、阅读器偏好     |
| 响应式     | Stream<T> 自动推送变更        | 读写后手动刷新               |
| 迁移策略   | MigrationStrategy（v1→v4）   | 无迁移，删除旧 key 即可      |

数据库连接：

```dart
QueryExecutor _openConnection() =>
    driftDatabase(name: "hikari_novel_database", native: const DriftNativeOptions(
      databaseDirectory: getApplicationSupportDirectory

```

数据库文件存储在应用支持目录（Android: `/data/data/<pkg>/app_flutter/`，Windows: `%APPDATA%/<pkg>/`），文件名为 `hikari_novel_database`。

### 5.2.2 五张表定义

> 源码：`lib/common/database/entity.dart`

#### BookshelfEntity — 书架表

```dart
class BookshelfEntity extends Table {
  TextColumn get aid => text()();      // 小说 ID（主键）
  TextColumn get bid => text()();      // 删除 ID
  TextColumn get url => text()();      // 详情页 URL
  TextColumn get title => text()();    // 小说标题
  TextColumn get img => text()();      // 封面 URL
  TextColumn get classId => text()();  // 书架分类号（0-5）

  @override
  Set<Column> get primaryKey => {aid};
}
```

wenku8 的书架分为 6 个分类（classId 0-5），登录时同步全部 6 个分类到本地。

#### BrowsingHistoryEntity — 浏览历史表

```dart
class BrowsingHistoryEntity extends Table {
  TextColumn get aid => text()();        // 小说 ID（主键）
  TextColumn get title => text()();      // 小说标题
  TextColumn get img => text()();        // 封面 URL
  DateTimeColumn get time => dateTime(); // 查看时间

  @override
  Set<Column> get primaryKey => {aid};
}
```

同一本小说多次浏览只保留最新记录（`insertOnConflictUpdate`）。

#### SearchHistoryEntity — 搜索历史表

```dart
class SearchHistoryEntity extends Table {
  TextColumn get keyword => text()();  // 搜索关键词（主键）

  @override
  Set<Column> get primaryKey => {keyword};
}
```

最简单的表，仅一个字段。相同关键词不会重复记录。

#### ReadHistoryEntity — 阅读历史表

```dart
class ReadHistoryEntity extends Table {
  TextColumn get cid => text()();         // 章节 ID（主键）
  TextColumn get aid => text()();         // 小说 ID
  IntColumn get readerMode => integer();  // 阅读模式（1=滚动, 2=翻页）
  BoolColumn get isDualPage => boolean(); // 是否双页
  IntColumn get location => integer();    // 阅读位置（滚动模式用）
  IntColumn get progress => integer();    // 阅读进度百分比
  BoolColumn get isLatest => boolean();   // 是否为最新阅读章节

  @override
  Set<Column> get primaryKey => {cid};
}
```

**核心设计**：`isLatest` 标记同一本小说中最后阅读的章节。进入小说详情页时，通过 `getLastestReadHistoryByAid(aid)` 获取上次阅读位置。

#### NovelDetailEntity — 小说详情缓存表

```dart
class NovelDetailEntity extends Table {
  TextColumn get aid => text()();  // 小说 ID（主键）
  TextColumn get json => text()(); // NovelDetail 的 JSON 字符串

  @override
  Set<Column> get primaryKey => {aid};
}
```

将 `NovelDetail` 对象序列化为 JSON 存储，避免重复请求详情接口。

## 5.3 Drift 数据库迁移

> 源码：`lib/common/migration.dart`

```dart
@override
MigrationStrategy get migration => MigrationStrategy(
  onUpgrade: (m, from, to) async {
    if (from == 1 && to == 2) {
      Migration.fromOneToTwo(this);
    } else if (from == 2 && to == 3) {
      Migration.fromTwoToThree();
    } else if (from == 3 && to == 4) {
      Migration.fromThreeToFour(this);
    }
  },
);
```

| 迁移路径 | 变更内容                                                     |
| -------- | ------------------------------------------------------------ |
| v1 → v2  | ① 删除 Hive loginInfo 中的明文用户名密码（安全修复）<br>② 删除旧缓存章节文件（数据源切换）<br>③ 重建 read_history_entity 表（Schema 变更） |
| v2 → v3  | 清除 Cookie，强制重新登录（接口变更）                        |
| v3 → v4  | 清空所有阅读历史（数据格式不兼容）                           |

**v1→v2 迁移链路**（最复杂的一次）：

```
1. 打开 Hive loginInfo Box
   → 删除 "username"、"password" 键（明文存储的安全隐患）

2. 获取应用支持目录
   → 删除 cached_chapter/ 目录（旧数据源的缓存）

3. 创建 read_history_entity_new 临时表
   → 从旧表拷贝数据到新表
   → 删除旧表
   → 重命名新表为 read_history_entity
```

## 5.4 DBService — Drift 服务封装

> 源码：`lib/service/db_service.dart`

```dart
class DBService extends GetxService {
  static DBService get instance => Get.find<DBService>();
  late final AppDatabase _db;

  void init() {
    _db = AppDatabase();
  }
  // ... 20+ 个方法直接委托给 _db
}
```

**设计意图**：薄封装层，所有方法直接委托给 `AppDatabase`。作用：
1. 统一通过 `DBService.instance` 访问，不暴露 `AppDatabase` 实例
2. 作为 `GetxService`，生命周期由 GetX 管理（`main()` 中 `Get.putAsync` 注册）

### Stream vs Future 方法

DBService 的方法分为两类：

| 返回类型              | 方法示例                             | 用途               |
| --------------------- | ------------------------------------ | ------------------ |
| `Stream<T>`           | `getBookshelfByClassId(classId)`     | UI 监听实时变更    |
| `Future<T>`           | `getAllBookshelf()`                   | 一次性查询         |

**Stream 链路**（以书架为例）：

```
UI 层：
  Obx(() {
    final books = DBService.instance.getBookshelfByClassId("0");
    // Stream<List<BookshelfEntityData>>
  })

DBService：
  → AppDatabase.getBookshelfByClassId("0")
    → (select(bookshelfEntity)..where((i) => i.classId.equals("0"))).watch()

Drift：
  → SQLite 查询 + 监听变更
  → 数据变更时自动推送新 List 到 Stream
  → Obx 自动重建 UI
```

### 阅读历史的事务逻辑

```dart
Future<void> upsertReadHistory(ReadHistoryEntityData data) => transaction(() async {
  // 1. 将同一本书的旧 "最新章节" 标记为 false
  await (update(readHistoryEntity)
    ..where((i) => i.isLatest.equals(true) & i.aid.equals(data.aid)))
    .write(RawValuesInsertable({readHistoryEntity.isLatest.name: Variable<bool>(false)}));
  // 2. 插入或更新新记录
  await into(readHistoryEntity).insertOnConflictUpdate(data);
});
```

**链路**：先将同一本书的旧 `isLatest=true` 记录改为 `false`，再插入新记录。两步操作在同一事务中执行，保证数据一致性。

## 5.5 Hive CE 存储层

### 5.5.1 初始化链路

> 源码：`lib/service/local_storage_service.dart`

```dart
Future<void> init() async {
  final Directory dir = await getApplicationSupportDirectory();
  final String path = dir.path;
  Hive.init("$path/hive");           // 1. 设置存储路径
  Hive.registerAdapters();           // 2. 注册 TypeAdapter
  _setting = await Hive.openBox("setting");      // 3. 打开 3 个 Box
  _loginInfo = await Hive.openBox("loginInfo");
  _reader = await Hive.openBox("reader");
}
```

**链路**：

```
main() → LocalStorageService.init()
  → getApplicationSupportDirectory()  // 获取应用支持目录
  → Hive.init("$path/hive")           // 初始化 Hive 存储路径
  → Hive.registerAdapters()            // 注册 UserInfo 的 TypeAdapter
  → Hive.openBox("setting")            // 打开设置 Box
  → Hive.openBox("loginInfo")          // 打开登录信息 Box
  → Hive.openBox("reader")             // 打开阅读器配置 Box
```

### 5.5.2 三个 Box 的职责划分

| Box 名     | 存储内容                                 | Key 数量 |
| ---------- | ---------------------------------------- | -------- |
| setting    | 主题、语言、节点、用户信息、自动更新等   | 10 个    |
| loginInfo  | Cookie（wenku8 登录态）                  | 1 个     |
| reader     | 阅读器全部配置（字体、边距、颜色、TTS 等） | 30+ 个   |

**为什么分三个 Box？**

- **语义隔离**：设置、登录、阅读器配置是三个独立领域
- **清理粒度**：`migration.dart` 中可以单独清空 `loginInfo` 而不影响其他配置
- **性能**：Box 越小，打开和读写越快

### 5.5.3 Key 常量定义

```dart
static const String kCookie = "cookie";
static const String kUserInfo = "user_info";
static const String kLanguage = "language";
static const String kThemeMode = "themeMode";
static const String kReaderFontSize = "readerFontSize";
// ... 共 30+ 个常量
```

所有 Key 集中定义为 `static const String`，避免硬编码字符串导致的拼写错误。

### 5.5.4 Getter/Setter 模式

每个配置项遵循统一模式：

```dart
// 布尔值
bool getIsAutoCheckUpdate() => _setting.get(kIsAutoCheckUpdate, defaultValue: true);
void setIsAutoCheckUpdate(bool enabled) => _setting.put(kIsAutoCheckUpdate, enabled);

// 枚举值（存储 index）
ThemeMode getThemeMode() => ThemeMode.values[_setting.get(kThemeMode, defaultValue: ThemeMode.system.index)];
void setThemeMode(ThemeMode tm) => _setting.put(kThemeMode, tm.index);

// 颜色值（存储 ARGB int）
Color getCustomColor() => Color(_setting.get(kCustomColor, defaultValue: Colors.blue.toARGB32()));
void setCustomColor(Color color) => _setting.put(kCustomColor, color.toARGB32());
```

**特殊处理**：
- **枚举**：存储 `.index`（int），读取时通过 `Values[index]` 还原
- **颜色**：存储 `.toARGB32()`（int），读取时通过 `Color(int)` 还原
- **Map**：TTS Voice 存储为 `Map<String, String>`，读取时做类型转换

## 5.7 完整数据流链路

### 5.7.1 登录 → 书架同步

```
LoginPage WebView 检测到 Cookie
  → LocalStorageService.setCookie(cookie)     // Hive: loginInfo
  → Api.getBookshelf(classId)                  // 网络请求 6 次
  → Parser.getBookshelf(html)                  // HTML 解析
  → DBService.insertAllBookshelf(data)         // Drift: 批量写入
  → Get.offAllNamed(RoutePath.main)            // 跳转主页
```

### 5.7.2 浏览小说 → 记录历史

```
NovelDetailController.getNovelDetail(aid)
  → DBService.upsertBrowsingHistory(data)      // Drift: 浏览历史
  → Api.getNovelDetail(url)                    // 网络请求
  → DBService.upsertNovelDetail(json)          // Drift: 详情缓存
```

### 5.7.3 阅读章节 → 记录进度

```
ReaderController.getContent(cid)
  → DBService.getReadHistoryByCid(cid)         // 查询已有进度
  → 显示内容

用户滑动/翻页
  → DBService.upsertReadHistory(data)          // Drift: 更新进度
    → transaction {
        更新旧 isLatest=false                  // 事务步骤 1
        插入新记录                              // 事务步骤 2
      }
```

### 5.7.4 修改设置 → 持久化

```
SettingsPage 用户修改主题色
  → LocalStorageService.setCustomColor(color)  // Hive: setting
  → Get.forceAppUpdate()                       // 刷新 UI
```

## 5.8 Hive vs Drift 选型对比

| 对比项     | Hive CE                  | Drift (SQLite)           |
| ---------- | ------------------------ | ------------------------ |
| 数据模型   | 键值对                   | 关系表                   |
| 查询能力   | 仅按 key 查询            | SQL 查询 + 条件过滤      |
| 响应式     | 无（需手动读取）         | Stream 自动推送          |
| 序列化     | TypeAdapter（自动生成）  | Table 定义（自动生成）   |
| 迁移       | 无迁移机制               | MigrationStrategy        |
| 性能       | 极快（二进制）           | 较快（SQL 解析）         |
| 适用场景   | 配置、简单存储           | 结构化业务数据           |

**Hikari Novel 的选型逻辑**：
- 配置项（主题、字体、边距）→ 键值对，按 key 读写 → **Hive**
- 书架（按分类查询、关键词搜索）→ 需要条件过滤 → **Drift**
- 阅读历史（按小说查询最新章节）→ 需要复合条件 → **Drift**
- 浏览历史（按时间排序）→ 需要排序 → **Drift**
