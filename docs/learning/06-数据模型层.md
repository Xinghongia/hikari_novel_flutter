## 6.2 序列化机制对比

项目中存在三种序列化方式：

| 方式 | 注解 | 生成文件 | 适用场景 |
|------|------|----------|----------|
| json_annotation | `@JsonSerializable` | `*.g.dart` | 需要 JSON 序列化的模型 |
| Hive CE | `@HiveType` + `@HiveField` | `*.g.dart` | 需要本地持久化的模型 |
| 手写 | 无 | 无 | 简单模型或特殊需求 |

生成命令：`dart run build_runner build --delete-conflicting-outputs`

## 6.3 ★ NovelDetail — 最核心的数据模型

> 源码：`lib/models/novel_detail.dart`

```dart
@JsonSerializable(explicitToJson: true)
class NovelDetail {
  final String title;           // 标题
  final String author;          // 作者
  final String status;          // 连载状态
  final String finUpdate;       // 最后更新时间
  final String imgUrl;          // 封面图 URL
  final String introduce;       // 简介
  final List<String> tags;      // 标签列表
  final String heat;            // 热度
  final String trending;        // 上升指数
  final bool isAnimated;        // 是否动画化
  List<CatVolume> catalogue = [];  // 目录（不属于 JSON 序列化）

  factory NovelDetail.fromJson(Map<String, dynamic> json) => _$NovelDetailFromJson(json);
  Map<String, dynamic> toJson() => _$NovelDetailToJson(this);

  // 用于 Drift 缓存：序列化为 JSON 字符串
  @override
  String toString() => jsonEncode(toJson());
  factory NovelDetail.fromString(String json) => NovelDetail.fromJson(jsonDecode(json));
}
```

### 序列化链路

```
网络请求 → Parser.getNovelDetail(html)
  → 手动解析 HTML 构造 Map<String, dynamic>
  → NovelDetail.fromJson(map)
  → _$NovelDetailFromJson()（生成代码）
  → NovelDetail 实例

Drift 缓存 → DBService.upsertNovelDetail(data)
  → NovelDetail.toString()
  → jsonEncode(toJson())
  → 存储为 JSON 字符串

Drift 读取 → DBService.getNovelDetail(aid)
  → 读取 JSON 字符串
  → NovelDetail.fromString(json)
  → jsonDecode → fromJson
  → NovelDetail 实例
```

### `explicitToJson: true` 的作用

嵌套对象（`List<CatVolume>`）在序列化时会调用每个元素的 `toJson()`，而不是只序列化为引用。没有这个参数，嵌套对象会被跳过。

## 6.4 CatVolume + CatChapter — 目录层级结构

> 源码：`lib/models/cat_volume.dart`、`lib/models/cat_chapter.dart`

```dart
// 卷
@JsonSerializable(explicitToJson: true)
class CatVolume {
  final String title;                    // 卷标题
  final List<CatChapter> chapters;       // 章节列表

  @JsonKey(includeFromJson: false, includeToJson: false)
  final RxBool isSelected;              // 选择状态（不序列化）

  CatVolume({required this.title, required this.chapters, bool initSelected = false})
    : isSelected = initSelected.obs;
}

// 章节
@JsonSerializable()
class CatChapter {
  final String title;                    // 章节标题
  final String cid;                      // 章节 ID

  @JsonKey(includeFromJson: false, includeToJson: false)
  final RxBool isSelected;              // 选择状态（不序列化）

  CatChapter({required this.title, required this.cid, bool initSelected = false})
    : isSelected = initSelected.obs;
}
```

### 层级关系

```
NovelDetail
  └── catalogue: List<CatVolume>
        ├── CatVolume[0] "第一卷"
        │     ├── CatChapter[0] {title: "序章", cid: "1001"}
        │     ├── CatChapter[1] {title: "第一章", cid: "1002"}
        │     └── CatChapter[2] {title: "第二章", cid: "1003"}
        └── CatVolume[1] "第二卷"
              ├── CatChapter[0] {title: "第三章", cid: "1004"}
              └── CatChapter[1] {title: "第四章", cid: "1005"}
```

### RxBool isSelected 的设计

```dart
@JsonKey(includeFromJson: false, includeToJson: false)
final RxBool isSelected;
```

- **用途**：小说详情页的「批量缓存」模式，用户可以勾选多个章节
- **`@JsonKey` 排除**：`isSelected` 是 UI 状态，不应参与 JSON 序列化和 Drift 缓存
- **`RxBool`**：GetX 响应式变量，`Obx()` 监听变化自动刷新 UI
- **默认值**：构造函数中 `initSelected = false`，通过 `.obs` 创建响应式变量

## 6.5 Resource<T> — 网络请求结果封装

> 源码：`lib/models/resource.dart`

```dart
sealed class Resource<T> {
  final T? data;
  final dynamic error;
  const Resource({this.data, this.error});
}

class Success<T> extends Resource<T> {
  const Success(T data) : super(data: data);
}

class Error extends Resource<void> {
  const Error([dynamic error]) : super(error: error);
}
```

### 使用链路

```
Api.getNovelDetail(url)
  → try {
      final response = await Request.get(url);
      final html = response.data;
      final detail = Parser.getNovelDetail(html);
      return Success(detail);           // 成功
    } catch (e) {
      return Error(e);                  // 失败
    }

Controller:
  final result = await Api.getNovelDetail(url);
  if (result is Success) {
    novelDetail.value = result.data;    // 使用数据
  } else if (result is Error) {
    showError(result.error);            // 显示错误
  }
```

### sealed class 的优势

Dart 3 的 `sealed class` 特性：
1. **穷尽性检查**：`switch` 语句必须处理所有子类，否则编译报错
2. **模式匹配**：`if (result is Success)` 可以直接访问 `result.data`
3. **类型安全**：`Success<T>` 携带数据类型，`Error` 只携带错误信息

### 为什么 Error 继承 Resource<void>？

`Error` 不携带业务数据，所以泛型参数为 `void`。这保证了类型安全：`Error` 实例的 `data` 字段始终为 `null`。

## 6.6 UserInfo — Hive 持久化模型

> 源码：`lib/models/user_info.dart`

```dart
@HiveType(typeId: 0, adapterName: "user_info_adapter")
class UserInfo {
  @HiveField(0)  final String avatar;        // 头像 URL
  @HiveField(1)  final String uid;           // 用户 ID
  @HiveField(2)  final String username;      // 用户名
  @HiveField(3)  final String userLevel;     // 等级
  @HiveField(4)  final String email;         // 邮箱
  @HiveField(5)  final String registerDate;  // 注册日期
  @HiveField(6)  final String contribution;  // 贡献值
  @HiveField(7)  final String experience;    // 经验值
  @HiveField(8)  final String point;         // 当前积分
  @HiveField(9)  final String maxBookshelfNum;  // 书架最大收藏量
  @HiveField(10) final String maxRecommendNum;  // 每天推荐次数
}
```

### 与 NovelDetail 的序列化对比

| 维度 | NovelDetail (@JsonSerializable) | UserInfo (@HiveType) |
|------|--------------------------------|---------------------|
| 序列化格式 | JSON 字符串 | 二进制（Hive 内部格式） |
| 生成代码 | `fromJson` / `toJson` | TypeAdapter |
| 存储位置 | Drift (SQLite) | Hive Box |
| 读写性能 | 较快（SQL 查询） | 极快（键值对） |
| 适用场景 | 需要条件查询 | 按 key 读写 |

## 6.7 简单数据模型

### NovelCover — 列表卡片

```dart
class NovelCover {
```

```dart
  final List<String> images;

```

`text` 是纯文本内容，`images` 是章节中插图的 URL 列表。

### Bookshelf — 书架

```dart
class Bookshelf {
  final List<BookshelfNovelInfo> list;
  final String classId;  // 书架分类号（0-5）

class BookshelfNovelInfo {
  final String bid;      // 删除 ID
  final String aid;      // 小说 ID
```

与 `CatVolume`/`CatChapter` 相同的设计：`RxBool isSelected` 用于选择模式，但 `BookshelfNovelInfo` 没有序列化注解（只用于 UI 层，不持久化）。

### RecommendBlock — 推荐区块

```dart

  final String title;           // 区块标题（如"热门推荐"）
  final List<NovelCover> list;  // 小说封面列表
}
```

### ChapterCacheTask — 缓存任务

```dart
class ChapterCacheTask {
  String uuid;              // 唯一 ID
  String aid;               // 小说 ID
  String cid;               // 章节 ID
  String title;
  CacheStatus status;       // 缓存状态
  double progress;          // 进度 0.0~1.0，-1 表示未知
  Function(String cid)? onCompleted;  // 完成回调

  Map<String, dynamic> toJson() => { ... };           // 手写序列化
  factory ChapterCacheTask.fromJson(Map<String, dynamic> json) => ...;
}
```

**特殊设计**：
- **手写 JSON 序列化**：没有使用 `@JsonSerializable`，因为需要自定义字段映射（如 `uuid` → `id`）
- **`onCompleted` 回调**：缓存完成时触发，用于通知 UI 更新
- **`CacheStatus` 枚举**：pending/downloading/paused/completed/failed/canceled

## 6.8 枚举类型

### CacheStatus — 缓存状态

```dart
enum CacheStatus { pending, downloading, paused, completed, failed, canceled }

String statusToString(CacheStatus s) => s.toString().split('.').last;
CacheStatus statusFromString(String s) => CacheStatus.values.firstWhere(
  (e) => e.toString().split('.').last == s,
  orElse: () => CacheStatus.pending,
);
```

手写序列化函数（`statusToString`/`statusFromString`），不依赖代码生成。

### PageState — 页面状态

```dart
enum PageState {
  loading, success, empty, error,
  pleaseSelect, jumpToOtherPage, inFiveSecond,
  bookshelfContent, bookshelfSearch, placeholder
}
```

10 种状态覆盖了页面生命周期的各种场景。

### DualPageMode — 双页模式

```dart
enum DualPageMode { auto, enabled, disabled }
```

`auto` 根据屏幕宽度自动判断是否启用双页。

### ReaderDirection — 阅读方向

```dart
enum ReaderDirection { leftToRight, rightToLeft, upToDown }
```

支持三种阅读方向：横滑左到右、横滑右到左、竖向滚动。

## 6.11 序列化选型决策树

```
需要序列化？
├── 是 → 需要本地持久化？
│   ├── 是 → 用 @HiveType（如 UserInfo）
│   └── 否 → 需要 JSON 序列化？
│       ├── 是 → 用 @JsonSerializable（如 NovelDetail, CatVolume）
│       └── 否 → 手写（如 ChapterCacheTask）
└── 否 → 纯 Dart 类（如 NovelCover, Content）
```
