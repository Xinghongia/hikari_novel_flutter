## 一、前置知识：Resource 密封类

在理解基类之前，先看网络请求的返回类型：

```dart
// lib/models/resource.dart
sealed class Resource<T> {
  final T? data;
  final dynamic error;
  const Resource({this.data, this.error});
}

class Success<T> extends Resource<T> {
  const Success(T data) : super(data: data);
}

class Error extends Resource<void> {
  const Error([dynamic error]) : super(error: error);
}
```

`sealed class` 是 Dart 3 的密封类，配合 `switch` 使用时编译器会检查是否穷尽所有子类。基类控制器的 `getPage()` 中 `switch (result)` 能自动推断类型，`result.data` 在 `Success` 分支中是非空的 `String`（HTML），在 `Error` 分支中 `result.error` 是错误信息。

## 三、BaseListPageController\<T\> — 自动加载型基类

**文件：** `lib/base/base_list_page_controller.dart`

完整源码：

```dart
abstract class BaseListPageController<T> extends GetxController {
  // ===== 子类必须实现 =====
  abstract Rx<PageState> pageState;       // 页面状态（子类决定初始值）
  Future<Resource> getData(int index);     // 发起网络请求，index 是页码
  List<T> getParser(String html);          // 将 HTML 解析为模型列表

  // ===== 基类提供的字段 =====
  String errorMsg = "";                    // 错误信息
  int _maxNum = 1;                         // 总页数（从 HTML 中解析）
  int _index = 0;                          // 当前页码
  final RxList<T> data = RxList();         // 数据列表（响应式）

  // ===== 生命周期 =====
  @override
  void onReady() {
    super.onReady();
    getPage(false);   // 页面就绪后自动首次加载
  }

  // ===== 登录跳转 =====
  void goLogin() {
    Get.toNamed(RoutePath.login);
  }

  // ===== 核心：分页引擎 =====
  Future<IndicatorResult> getPage(bool loadMore) async {
    // 1. 首次加载：重置状态
    if (!loadMore) {
      pageState.value = PageState.loading;
      data.clear();
      _index = 0;
    }

    // 2. 判断是否还有更多页
    if (_index >= _maxNum) return IndicatorResult.noMore;

    // 3. 请求下一页
    _index += 1;
    final result = await getData(_index);

    // 4. 处理结果
    switch (result) {
      case Success():
        {
          // 4a. 检查是否是 wenku8 的错误页面（需要登录）
          if (Parser.isError(result.data)) {
            if (!loadMore) {
              errorMsg = "need_login_to_browse".tr;
              pageState.value = PageState.needLogin;
            } else {
              Get.dialog(AlertDialog(...));  // 加载更多时弹对话框
            }
            if (_index > 0) _index -= 1;    // 回退页码
            return IndicatorResult.fail;
          }

          // 4b. 首次加载时解析总页数
          if (!loadMore) _maxNum = Parser.getMaxNum(result.data);

          // 4c. 解析数据并追加到列表
          data.addAll(getParser(result.data));

          pageState.value = PageState.success;
          return IndicatorResult.success;
        }
      case Error():
        {
          // 4d. 首次加载显示错误页，加载更多弹对话框
          if (!loadMore) {
            pageState.value = PageState.error;
            errorMsg = result.error;
          } else {
            showErrorDialog(result.error.toString(), [...]);
          }
          if (_index > 0) _index -= 1;
          return IndicatorResult.fail;
        }
    }
  }
}
```

### 完整调用链（以评论页为例）

```
用户点击小说详情页的"评论"按钮
  │
  ▼

  │  调用 _toContentPage("/comment", arg: "12345")
  │  Get.toNamed("/comment", arguments: "12345", id: 1)
  │
  ▼

  │  case RoutePath.comment:
  │    return GetPageRoute(page: () => CommentPage(aid: "12345"))
  │
  ▼
CommentPage 构造函数
  │  controller = Get.put(CommentController(aid: "12345"))
  │  → GetX 创建 Controller 实例，调用 onInit()
  │
  ▼
CommentController extends BaseListPageController<CommentItem>
  │  实现了三个抽象成员：
  │    pageState = Rx(PageState.loading)
  │    getData(index) → Api.getComment(aid: "12345", index: index)
  │    getParser(html) → Parser.getComment(html)
  │
  ▼
CommentPage.build()
  │  渲染 Stack，包含 4 个 Offstage：
  │    success → EasyRefresh + ListView（显示数据）
  │    loading → LoadingPage（加载动画）
  │    error   → ErrorMessage（错误提示）
  │    needLogin → LoginPrompt（登录提示）
  │
  ▼
GetX 生命周期触发 onReady()
  │  调用 getPage(false)
  │
  ▼

  │  ① pageState = loading → UI 显示 LoadingPage
  │  ② _index = 0 → _index++ = 1
  │  ③ getData(1) → Api.getComment(aid, index: 1) → HTTP 请求
  │  ④ 返回 Success(html)
  │  ⑤ Parser.isError(html)? → false → 继续
  │  ⑥ Parser.getMaxNum(html) → _maxNum = 3（假设3页）
  │  ⑦ Parser.getComment(html) → [CommentItem, CommentItem, ...]
  │  ⑧ data.addAll([...]) → UI 自动刷新 ListView
  │  ⑨ pageState = success → Offstage 切换，显示 ListView
  │  ⑩ return IndicatorResult.success
  │
  ▼
用户下拉刷新 → EasyRefresh 调用 onRefresh
  │  → controller.getPage(false)
  │  → 重新从第1页加载
  │
  ▼
用户上拉加载更多 → EasyRefresh 调用 onLoad
  │  → controller.getPage(true)
  │  → loadMore=true，不清空 data，_index 继续递增
  │  → 请求第2页，追加到 data
  │  → 如果 _index >= _maxNum，返回 IndicatorResult.noMore
```

## 四、BaseSelectListPageController\<T\> — 手动触发型基类

**文件：** `lib/base/base_select_list_page_controller.dart`

与 `BaseListPageController` 的核心区别：

| 对比项 | BaseListPageController | BaseSelectListPageController |
|--------|----------------------|------------------------------|
| 初始状态 | 子类声明（通常 `loading`） | 固定 `pleaseSelect` |
| `onReady()` | 自动调用 `getPage(false)` | **无**，不自动加载 |
| `easyRefreshController` | 无 | 有，用于手动触发刷新 |
| 使用场景 | 页面打开就加载 | 需要用户先选择条件 |

`getPage()` 的实现逻辑完全相同，区别仅在触发时机。

### CategoryController 关键代码

```dart
class CategoryController extends BaseSelectListPageController<NovelCover> {
  RxString category = "please_select".tr.obs;   // 分类条件
  RxString sortText = "please_select".tr.obs;    // 排序文字
  String sortValue = "";                          // 排序值（"0"/"1"/"2"/"3"）

  @override
  void onInit() {
    super.onInit();
    // 监听两个条件，都选好后自动触发刷新
    everAll([category, sortText], (_) {
      if (category.value != "please_select".tr && sortText.value != "please_select".tr) {
        easyRefreshController.callRefresh(force: true);
      }
    });
  }

  @override
  Future<Resource> getData(int index) =>
    Api.getNovelByCategory(category: category.value, sort: sortValue, index: index);

  @override
  List<NovelCover> getParser(String html) => Parser.parseToList(html);
}
```

注意：`sortValue` 不是 `Rx` 响应式的，因为它的变化不需要触发 UI 更新，只需要在 `getData()` 调用时读取最新值即可。

### 5.3 子导航器的创建

```dart
// lib/pages/main/view.dart
Widget _buildContentNavigator(MainController controller) {
  return PopScope(
    canPop: false,
    onPopInvokedWithResult: (didPop, _) {
      if (!didPop) {
        // 处理返回键：先尝试子导航器 pop，再尝试主导航器 pop
        if (AppSubRouter.subNavigatorKey!.currentState!.canPop()) {
          AppSubRouter.subNavigatorKey!.currentState!.pop();
        } else if (Navigator.canPop(Get.context!)) {
          Get.back();
        }
      }
    },
    child: ClipRect(
      child: Navigator(
        key: AppSubRouter.subNavigatorKey,     // GlobalKey，用于手动操作
        initialRoute: RoutePath.logo,           // 默认显示 LogoPage
        observers: [SubNavigatorObserver()],    // 监听路由变化
        onGenerateRoute: (settings) => AppRoutes.subRoutePages(settings),
      ),
    ),
  );
}
```

关键点：
- 使用 Flutter 原生的 `Navigator` widget（不是 GetX 的），通过 `Get.nestedKey(1)` 获取 key
- `onGenerateRoute` 回调到 `AppRoutes.subRoutePages()` 进行路由分发
- `PopScope` 拦截返回键，优先在子导航器内 pop

### 5.4 子路由监听器

```dart
// lib/pages/main/view.dart
class SubNavigatorObserver extends NavigatorObserver {
  @override
  void didPush(Route route, Route? previousRoute) {
    super.didPush(route, previousRoute);
    if (previousRoute != null) {
      var routeName = route.settings.name ?? "";
      AppSubRouter.currentContentRouteName = routeName;
      // 显示内容区（非 logo 页时）
      Get.find<MainController>().showContent.value = routeName != RoutePath.logo;
    }
  }

  @override
  void didPop(Route route, Route? previousRoute) {
    super.didPop(route, previousRoute);
    var routeName = previousRoute?.settings.name ?? "";
    AppSubRouter.currentContentRouteName = routeName;
    // 回到 logo 页时隐藏内容区
    Get.find<MainController>().showContent.value = routeName != RoutePath.logo;
  }
}
```

效果：子路由 push 时自动显示内容区，pop 回 logo 时自动隐藏。

### 5.5 AppSubRouter — 子路由导航器

```dart
// lib/router/app_sub_router.dart
class AppSubRouter {
  static String currentContentRouteName = RoutePath.logo;  // 当前路由名
  static final int subNavigatorId = 1;                      // 嵌套导航器 ID
  static final GlobalKey<NavigatorState>? subNavigatorKey = Get.nestedKey(1);
  static bool _isNavigating = false;                        // 防抖标志

  // 核心导航方法
  static void _toContentPage(String name, {dynamic arg, bool replace = false}) {
    if (_isNavigating) return;   // 500ms 内忽略重复调用
    _isNavigating = true;

    if (currentContentRouteName == name || replace) {
      // 同一路由再次进入（如连续点两本小说）→ 替换当前页面
      Get.offAndToNamed(name, arguments: arg, id: subNavigatorId);
    } else {
      // 新路由 → 压入导航栈
      Get.toNamed(name, arguments: arg, id: subNavigatorId);
    }

    Future.delayed(const Duration(milliseconds: 500), () {
      _isNavigating = false;
    });
  }

  // 公开方法
  static void toNovelDetail({required String aid}) =>
    _toContentPage(RoutePath.novelDetail, arg: aid);

  static void toComment({required String aid}) =>
    _toContentPage(RoutePath.comment, arg: aid);

  static void toReply({required String aid, required String rid}) =>
    _toContentPage(RoutePath.reply, arg: [aid, rid]);  // 两个参数打包成 List

  static void toSearch({required String? author}) =>
    _toContentPage(RoutePath.search, arg: author);  // 可为 null
  // ... 其他方法类似
}
```

### 5.7 AppRoutes.subRoutePages — 子路由表

// lib/router/app_pages.dart
static Route<dynamic>? subRoutePages(RouteSettings settings) {
  switch (settings.name) {
    case RoutePath.logo:
      return GetPageRoute(settings: settings, page: () => LogoPage());
    case RoutePath.novelDetail:
      var args = settings.arguments as String;
      return GetPageRoute(settings: settings, page: () => NovelDetailPage(aid: args));
    case RoutePath.comment:
      var args = settings.arguments as String;
      return GetPageRoute(settings: settings, page: () => CommentPage(aid: args));
    case RoutePath.reply:
      var args = settings.arguments as List<String>;
      return GetPageRoute(settings: settings, page: () => ReplyPage(aid: args[0], rid: args[1]));
    case RoutePath.search:
      var args = settings.arguments as String?;
      return GetPageRoute(settings: settings, page: () => SearchPage(author: args));
    case RoutePath.userBookshelf:
      var args = settings.arguments as String;
      return GetPageRoute(settings: settings, page: () => UserBookshelfPage(uid: args));
    // ... 其他路由
    default:
      return null;  // 未知路由返回 null
  }
}

## 七、不使用基类的页面 — RecommendController

推荐页没有继承基类，因为它的数据结构特殊（`RecommendBlock` 而非列表分页）：

```dart
class RecommendController extends GetxController {
  final RxList<RecommendBlock> data = RxList();
  Rx<PageState> pageState = Rx(PageState.loading);
  String errorMsg = "";

  @override
  void onReady() {
    super.onReady();
    getRecommend();   // 手动调用，不依赖基类
  }

  Future<IndicatorResult> getRecommend() async {
    pageState.value = PageState.loading;
    final result = await Api.getRecommend();
    switch (result) {
      case Success():
        if (Parser.isError(result.data)) {
          errorMsg = "need_login_to_browse".tr;
          pageState.value = PageState.needLogin;
          return IndicatorResult.fail;
        }
        data.clear();
        data.addAll(Parser.getRecommend(result.data));
        pageState.value = PageState.success;
        return IndicatorResult.success;
      case Error():
        errorMsg = result.error;
        pageState.value = PageState.error;
        return IndicatorResult.fail;
    }
  }
}
```

虽然不继承基类，但遵循相同的模式：`getData → switch(result) → 更新 pageState`。

|------|-----------|----------|---------|
| 分类 | CategoryController | NovelCover | category + sortText 都选择后 |
| 排行榜 | RankingController | NovelCover | ranking 选择后 |

### 不使用基类的页面

| 页面 | 原因 |
|------|------|
| 推荐 | 数据是 RecommendBlock 块，不是简单列表分页 |
| 搜索 | 有复杂的搜索逻辑和分页 |
| 小说详情 | 单页数据，非列表 |
| 书架 | 有 tab 切换和搜索模式 |

## 九、关键设计总结

| 设计 | 作用 | 代码位置 |
|------|------|---------|
| 模板方法模式 | 子类只实现 `getData()` + `getParser()` | base/*.dart |
| Resource 密封类 | 类型安全的网络结果处理 | models/resource.dart |
| PageState 枚举 | 统一的页面状态机 | models/page_state.dart |
| Offstage + Obx | 响应式状态切换（不销毁 widget） | 所有 view.dart |
| 嵌套 Navigator(id=1) | 持久壳 + 内容区独立切换 | main/view.dart |
| SubNavigatorObserver | 路由变化时自动显示/隐藏内容区 | main/view.dart |
| AppSubRouter 防抖 | 500ms 内忽略重复导航 | router/app_sub_router.dart |
| PopScope | 返回键优先在子导航器内 pop | main/view.dart |
| everAll 监听 | 条件满足后手动触发刷新 | category/ranking controller |
